# ゲーム特有の設計思想 (Game Design Philosophy)

本プロジェクトでは、React（UI）とゲームロジック（DDD）を調和させるために、以下の設計思想を取り入れます。

---

## 1. コア思想：ゲームループとUI描画の分離

Webアプリでは「イベント駆動」が基本ですが、ゲームでは**時間経過（Tick）による状態変化**が存在します。

- **課題**: Reactの `useState` だけで毎フレーム座標を更新すると、パフォーマンスが崩壊します。
- **解決策**: 
  - ゲームのコアな状態は **純粋なTypeScriptのドメインモデル（Entity）** に持たせます。
  - `requestAnimationFrame` を用いた**ゲームループ（Tick）**で Entity の状態を更新します。

## 2. エンティティとドメインの分離（Core vs Game Specific）

プラットフォーム共通の概念と、ゲーム個別のロジックを厳密に分離します。

- **`GameSession` (Core)**:
  - スコア、プレイ時間、プレイヤー情報を管理する汎用エンティティ。ゲームの物理的な進行（座標移動など）は一切関知しない。
- **`InvaderGameEngine` (Invader Specific)**:
  - インベーダーゲーム固有のロジック。
  - `tick(deltaTime)`: インベーダーの `move` 呼び出し、防衛ライン突破の判定などを行い、必要に応じて `GameSession` にスコア加算などのメッセージを送る。

## 3. UIへの状態同期最適化（React連携）

純粋なTSクラスからReactへの状態同期における過剰レンダリングを防ぐため、以下の手法を採用します。
- **`useSyncExternalStore` または `Zustand` の活用**:
  - ドメインの更新をReactが効率よくサブスクライブ（購読）し、必要なコンポーネントだけが再レンダリングされるアダプターパターンを構築します。
- **Canvas描画の併用**:
  - 更新頻度が極めて高い座標情報（インベーダー本体など）はCanvasに直接描画し、ReactのDOMツリーから切り離すハイブリッド設計を視野に入れます。

## 4. キーボードイベントのグローバル監視とガード

タイピングゲームにおけるキーボード入力監視（`features/keyboard-input`）には厳格なライフサイクル管理が必要です。

- **フォーカス管理（ガードロジック）**:
  - 「ゲームプレイ中」かつ「ゲーム画面（Canvas/DOM）にフォーカスが当たっている時」のみ入力を受け付けます。
  - ユーザーが別タブを開いている時、ポーズ中、あるいは設定モーダルなどの入力欄にフォーカスがある時は、タイピング判定が誤発火しないようガードします。

## 5. ローマ字入力の「揺らぎ」吸収

- 出題される単語（`TargetWord`）と、プレイヤーの現在の入力状態・バッファ（`ActiveWord`）を分離し、`entities/core/` 配下の純粋なドメインロジックとしてカプセル化します。UI側では単に打鍵された文字を渡すだけに留めます。

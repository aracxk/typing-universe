# ADR (Architecture Decision Records) - 意思決定記録

このディレクトリ（`03-adr/`）は、プロジェクトにおける**「なぜその設計・技術を選んだのか（Why）」**を記録するための場所です。

## 目的
- 後からプロジェクトに参加した人（や未来の自分、AI）が、「なぜこのライブラリを入れたのか」「なぜこのアーキテクチャにしたのか」という背景を理解できるようにする。
- 議論の堂々巡りを防ぐ。

## ADRの書き方

新しい技術選定や大きな設計判断（ルールの変更など）を行った際は、以下のフォーマットで番号付きのMarkdownファイル（例：`0001-xxx.md`）を作成してください。

```markdown
# [タイトル: 決定事項を簡潔に]

- **日付**: YYYY-MM-DD
- **ステータス**: [ 提案中 | 承認済 | 非推奨 | 変更済 ]

## コンテキスト（背景と課題）
- なぜその決定が必要になったのか。
- どのような課題があったのか。

## 決定事項（Decision）
- 何を採用（または不採用）にしたか。

## 理由（Why / トレードオフ）
- 他の選択肢ではなく、それを選んだ理由は何か。
- どのようなメリットがあり、どのようなデメリット（妥協点）を受け入れたか。
```

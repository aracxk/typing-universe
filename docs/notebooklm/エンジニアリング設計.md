# Typing Universe エンジニアリング設計

## 1. 実行環境とインフラ
- **ホスティング**: Vercel
- **データベース**: 不使用（Supabase等は使わず、ステートやハイスコアはブラウザのLocalStorage等で管理する）
- **フレームワーク**: Next.js (App Router), TypeScript, Tailwind CSS

## 2. ツールチェーン（開発基盤）
- **フォーマッター＆リンター**: `Biome`（超高速な静的解析。ESLint/Prettierは使用しない）
- **コミットフック**: `Husky` + `lint-staged`（コミット前に自動で Biome check を実行し、品質を強制）
- **テスト**: `Vitest`（TypeScriptネイティブで高速なドメインロジック検証）

## 3. アーキテクチャの基本方針
- **Feature-Sliced Design (FSD)**
  - 複数ゲームの共存を想定し、機能ごとに垂直にスライスする。
  - `entities/word/`（プラットフォーム共通）と `entities/invader/`（特定のゲーム固有）などのドメイン分割を行い、ゲーム間の直接的な依存を禁止する。

## 4. UI/UXデザインの基本方針（重要）
- **コンポーネントライブラリの不使用**: `shadcn/ui` や MUI 等の既存UIライブラリは**一切使用しない**。
- **AI主導のデザイン**: デザインはAI（Jules, Spark等）が Tailwind CSS を駆使してゼロから自律的に考え、ゲームの世界観に合ったクリエイティブなUIを都度構築する。

## 5. ゲーム特有の設計制約
- **ゲームループとReactの分離**
  - 時間経過（Tick）による状態変化（敵の移動など）は純粋なTypeScriptクラス（Entity）で管理し、`requestAnimationFrame` 等を用いたゲームループで更新する。
  - パフォーマンス崩壊を防ぐため、高頻度な再レンダリングを伴う箇所にはCanvasや `useSyncExternalStore` / Zustandの利用を検討し、Reactの `useState` への過度な依存を避ける。
- **ローマ字の揺らぎ吸収**
  - 日本語入力の揺らぎ吸収ロジックは、UI層ではなく `ActiveWord` のような専用ドメインモデル内に完全にカプセル化し、徹底的に単体テストを行う。

## 5. 高度なアーキテクチャ・テスト制約 (ai-note-market由来)
1. **ドメイン層のカバレッジ100%**: `src/entities/**/domain/` におけるテストカバレッジ（Branch, Function, Line, Statement）は例外なく100%を必須とします。
2. **Flyweight パターン**: 60FPSでのGCスパイクを防ぐため、頻出するValue Objectはキャッシュして再利用します。
3. **Hooksの絶対分離**: `.tsx` ファイル内での `useState/useEffect` を禁止し、すべてのロジックを Custom Hook へ隔離します。
4. **DDD基盤の活用**: 例外の代わりに `Result<T, E>` を使用し、すべてのエンティティ・値オブジェクトは `shared/domain/` の基底クラスを継承します。
